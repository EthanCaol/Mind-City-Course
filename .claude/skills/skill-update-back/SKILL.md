# 回写 skill 经验

本次会话执行过 skill
把执行中暴露的新场景, 踩坑与用户纠正补回对应 skill 的正文
目的是下次执行同一 skill 时不再重复探索

## 确定目标 skill

按以下顺序判断, 前一步能得到结果就不再往下走

1. 本次会话中读过或调用过的 `.claude/skills/<name>/SKILL.md`, 以主导流程的那个为主
2. 执行过的脚本与命令, 反查它们所在的 skill 目录
3. 上下文被压缩, 细节丢失时, 读当前会话记录
   `C:\Users\16770\.claude\projects\C--Users-16770-Desktop-Mind-City\<会话 id>.jsonl`
   `<会话 id>` 取该目录下最近修改的一个
   文件较大, 用脚本按行抽取 skill 路径, 命令与报错, 不整份读进上下文
4. 仍无法确定, 或者有多个候选时, 用 AskUserQuestion 问用户

一条流程调用了多个 skill 时
把现象写进最该负责的那个 skill, 不重复回写

## 抽取可回写的条目

优先找这几类

- 新场景: 正文没提到的输入类型, 环境, 依赖, 前置条件
- 适用条件: 正文的做法在本次不成立, 或只在某类情况下成立
- 踩坑与排查: 花多轮才定位的问题, 以及最终找到原因的手段
- 成功步骤: 本次一次走通的可靠顺序, 与正文不同时替换正文
- 用户纠正: 用户明确指出的做法差异或风格要求

只写会话内有证据的条目
证据指实际出现过的命令, 报错文本, 产物, 用户原话

写根因与做法, 不写表象
例如写「解压前设 `PYTHONIOENCODING=utf-8`, 否则中文报错乱码」
不写「遇到过乱码」

## 决定写在哪

写入前在 skill 目录内用关键词 grep 一次, 确认没有相同条目

- 找到与该条目对应的步骤或小节, 改那里的说法
- 已有条目能覆盖时, 在原条目上补条件, 不另起一条
- 与旧说法冲突时, 以本次证据为准改写, 删掉旧说法, 不留两句并存

## 写入

- 只改证据指向的 skill 文件, 不顺手重排无关段落
- 保持该文件现有的标点, 编号与措辞
- 用词按仓库根 `CLAUDE.md` 的「文风」一节
- 一条经验对应一处修改, 不做顺带重构
- 具体的主机名, 端口, 版本号, 绝对路径, 标明适用条件或写成判据, 不当成通用步骤

## 复查

- 改动是否与 skill 其他小节矛盾, 同一现象是否在两处重复
- 是否把一次性情况写成通用规则
  判据: 换个时间, 换台机器, 换一个 agent 执行同一 skill, 这条还成立
- 是否把主 agent 自己的操作失误记成 skill 的缺陷, 例如路径拼错, 参数写错
- 条目是否具体可执行, 有没有写成「注意兼容性」这类空泛原则
- 一次性环境故障不写, 例如网络抖动, 临时权限; 反复出现或属于固定约束的才写

## 报告

- 改了哪个 skill 的哪一步, 改成什么
- 每条改动的依据: 会话里的命令, 报错或用户原话
- 观察到但未写回的现象及原因
- 需要用户决定的事项

## 注意

- 回写的依据是本次会话, 不是通用最佳实践, 不添加与本次执行无关的建议
- 新会话中上下文已被清除且读不到会话记录时无法复盘, 直接说明并结束
- 不建独立经验文件与变更账本
