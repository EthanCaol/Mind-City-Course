# 用途

把学生答题照片转成可编译的 C 代码, 记录转录中拿不准的位置, 最后按参考解和评分权重统一写给分建议

# 批改基调

以下两条贯穿转录, 评议与给分, 与后面的细则冲突时以本节为准

- 这是程序设计课的期中纸面考试, 按手写的卷面代码批改, 不按机考的严格程度
  不要求代码能一次编译通过, 不要求处理非法输入, 不要求防御性写法与工程规范
  只看思路是否成立, 样例能不能得到正确结果
- 学生是刚结束高考的大一新生, 很多人第一次接触电脑
  拼写错误, 漏分号, 漏声明, 缺 `&`, 格式串写错, 变量名不规范这类问题很普遍
  这类问题记 0-9 一段, 合并成一条列出即可, 不从重扣分, 也不因为一份代码里有多处就叠加

# 目录结构

```
期中考卷批改/
  期中题目.md            试卷原文, 含每题参考代码
  花名册.txt             每行 "学号 姓名", UTF-8, 空格分隔
  额外校对表.md          转录疑点汇总
  学号-姓名/             每名学生一个文件夹
    学号-姓名.jpg        答题照片, 与代码放在一起
    学号-姓名-第一题.c
    学号-姓名-第二题.c
    学号-姓名-第N题-代码评议.md
    学号-姓名-第N题-代码评分.md
```

- 照片归入各自的学生文件夹, 不单独建 `编程题照片/` 汇集目录
- 分多批处理时, 处理期间可临时建 `第一批/` `第二批/` 各自存放照片与学生文件夹, 每批处理完再合并回上面的扁平结构
- 同一学生两题分两张照片时, 分别命名为 `学号-姓名-第一题.jpg` 与 `学号-姓名-第二题.jpg`
- 有背面内容时加后缀 `-背面`, 例如 `学号-姓名-背面.jpg`
- 学号 11 位, 从花名册按姓名查得
- 手写姓名与花名册对不上时, 向用户确认, 不自行猜测
- 照片上看不出姓名时, 记入校对表顶部的「图片名称 / 疑似」表, 等用户确认后再重命名与归档

# 流程

1. 读 `期中题目.md` 的编程题部分与 `花名册.txt`
2. 逐张照片处理
   - 先整图通读, 判断姓名与题号
   - 看不清的局部用 PIL 裁切放大后再读, 见「读图」一节
   - 转录到该学生文件夹下, 第 1 题写 `学号-姓名-第一题.c`, 第 2 题写 `学号-姓名-第二题.c`
3. 处理完一张, 把照片重命名为 `学号-姓名.jpg` 并移入该学生的文件夹
   - 一张照片覆盖两题时只保留一份原图, 不拆到题目目录
   - 照片原本集中在 `编程题照片/` 时, 用脚本按文件名前缀匹配学生文件夹再移入, 移完该目录应为空
4. 全部转完后, 每个 `.c` 文件生成一份代码评议, 见「代码评议」一节
5. 给分细则确定后, 每个 `.c` 文件生成一份代码评分, 见「代码评分文件」一节
   - 给分细则还没定下来时, 只做第 4 步
   - 分数按 0.1 分为单位, 例如 10.1, 11.5, 不凑整

# 转录规则

- 原样转录, 不修正错误, 不补遗漏, 不改变变量名
- 例外: 缺分号, 以及 `for` 里用逗号分隔条件, 用户确认按笔误处理时直接在 `.c` 里改对
  - 缺分号补 `;`; 条件处写成 `i < n, j < m` 的改成 `i < n && j < m`
  - `for (i = 0, i < n / 2, i++)` 整行用逗号代替分号的, 三段之间改回 `;`
  - 初始化与自增处的逗号是合法写法, 例如 `for (i = 0, j = 0; i < j; i++, j--)`, 不动
  - 改完用 `gcc -std=c99 -fsyntax-only 文件.c 2>&1 | grep "expected ';'"` 复查, 报错清零
- 文件开头写三行注释, 空一行后接代码

```
// 期中考试-编程题-第一题
// 学号: xxxxxxxx
// 姓名: 矫安然
```
- 空白类差异 (例如 `scanf("%s ")` 与 `scanf("%s")`, 括号内空格) 无法判断原意时, 一律取最规范的写法
- 小的涂改与墨迹不写进校对表, 直接按最终的写法转录
- 转义符的斜杠方向笔误, 例如把 `\n` 写成 `/n`, 统一改成正确写法, 也不写入校对表
- 明显是笔误但字迹清楚的内容 (例如把 `toupper` 写成 `supper`) 保留原样, 不改
- 影响代码含义、无法从上下文确定的疑点写入 `额外校对表.md`, 并在 `.c` 中按最可能的读法转录
- 用 `gcc -std=c99 -fsyntax-only 文件.c` 检查语法, 不生成可执行文件, 不修改代码
- 编译选项按写法灵活降级: 先用 `c99`, 不通过再试 `-std=gnu89`, 两种标准下的结果都记下来
  - 把 `int i` 写在 `for` 里, 使用变长数组, 属于 C99 写法, `gnu89` 下会报错, 这类文件只能按 C99 判断
  - `gets` 在 C11 中已移除, 只有 C99 及更早的标准能通过, 用到 `gets` 的文件必须降级检查
- gcc 14 起未声明函数按错误处理, 只缺头文件的文件在 C99 下会编译失败
- `-fsyntax-only` 不做链接, 不存在的函数 (例如 `supper`) 要到链接阶段才报 `undefined reference`
  这类文件再用 `gcc -std=gnu89 文件.c -o /tmp/x` 确认一次是否有链接错误
- 编译结果用于判断能否运行; 警告本身不当作缺陷, 但对应实际错误的警告要写进评议, 例如 `scanf` 缺 `&`
- 考试是手写代码, 编译不通过非常常见, 编译结果不作为严重程度的主要依据
  编译通过最多按附加 1 分计, 不单独决定扣分幅度

# 代码格式化

用户要求统一格式化 `.c` 时, 用 clang-format 批量处理

- 本机未装时 `sudo apt-get install -y clang-format`, Ubuntu 26.04 上装到的是 clang-format 21
- 配置写在 `期中考卷批改/.clang-format`, 与 `.vscode/settings.json` 里的 `C_Cpp.clang_format_fallbackStyle` 一致

```yaml
BasedOnStyle: WebKit
IndentWidth: 4
ColumnLimit: 120
AlignTrailingComments: true
IndentCaseLabels: true
BreakTemplateDeclarations: true
```

- 执行 `find . -name '*.c' -print0 | xargs -0 clang-format -i`
- 格式前把全部 `.c` 备份到仓库外的临时目录, 用于逐文件对比
- 格式化会把缺分号处的两行并成一行, 例如 `int i = 0, n, t` 与下一行合并成
  `int i = 0, n, t int len1, len2;`, 转录失真, 缺分号也看不出来
  格式后逐文件看 diff, 把这类行拆回两行再改
- 逐个文件比较行数, 行数有变化的文件列出, 评议里对应的「第 N 行」要重算
  用户说明之后会重评时, 不必回改评议

# 读图

- 依据 `PIL` 裁切并放大局部, 倍数取 1.5 到 2
  用 `Image.LANCZOS` 重采样, 存成 PNG 再读
- 脚本写在 `%TEMP%` 下, 不写进仓库; 临时图片同样放 `%TEMP%`
- 控制台编码为 GBK, 脚本里不打印中文

# 额外校对表

列固定为

| 是否已人工校对 | 学号-姓名 | 题号 | 不清楚率 | 位置行号百分数 | 不清楚的位置 | 猜测可能是 |
| -------------- | --------- | ---- | -------- | -------------- | ------------ | ---------- |

- 是否已人工校对: 留空表示待核对, 用户确认后填 1
- 不清楚率: 主观估计这条记录与原意不一致的可能性, 写成百分比
  越高表示越需要用户优先查看
- 位置行号百分数: 写成 0.xx, 等于该行在对应 `.c` 文件中的行号除以文件总行数
  同一段代码行数变化时同步更新
- 不清楚的位置: 引用代码片段, 说明疑点在哪
- 猜测可能是: 已采取的转录方式, 与可能的其他读法

身份不明的照片单独汇总在表格上方的「图片名称 / 疑似」表

| 图片名称 | 疑似 |
| -------- | ---- |

- 图片名称: 照片的原始文件名
- 疑似: 按可能性排列的候选姓名, 没有线索时写 —
- 用户确认身份后, 把照片改成 `学号-姓名.jpg` 并删掉这一行

# 代码评议

给分细则未定, 或需要先看清每个文件的问题时使用
每个 `.c` 文件一份, 与代码同目录, 命名为 `学号-姓名-第N题-代码评议.md`
不改 `.c`, 不写分数, 只列缺陷

## 评议结构

```
# 25300980087-矫安然-第一题 代码评议

| 问题编号 | 严重程度 |
| -------- | -------- |
| 1        | 1        |
| 2        | 1        |

严重程度标尺
- 90-100 核心功能未实现, 或结果完全错误
- 60-89 主要用例结果错误, 逻辑有实质缺陷
- 30-59 仅边界或特定输入出错
- 10-29 输出格式偏差, 题面违规
- 0-9 语法笔误, 可读性与风格

------

(1) 变量 `t` 未声明

第 20 行 `t = A[i][j];` 与第 22 行 `A[n - i - 1][j] = t;` 使用了未声明的变量 `t`
函数开头补 `int t;` 即可

------

(2) 列间使用制表符, 与样例不符

第 29 行 `printf("%d\t", A[i][j]);` 列间是制表符
题面样例用单个空格分隔, 改成 `"%d "` 即可

第 18-25 行用交换完成上下翻转, 第 27-33 行的两层输出与换行都正确

```

## 规则

- 正文不设「正确性问题」「输出格式问题」「过时写法」这类小节标题
- 不写分数, 也不写扣分幅度, 评分标准由用户单独确定后再统一算总分
  条目里只写位置, 原因与改法, 不出现「一般扣 N 分」这类句子
- 条目按严重程度从高到低排列, 编号全篇连续
- 相邻两个条目之间用一行 `------` 分割, 分割线前后各空一行
- 每条先写问题标题, 空一行, 再写具体行号与原因
- 行号对应被分析的 `.c` 文件, 不引用照片或原题的行号
- 表格行的顺序与正文编号一致
- 多条同类问题合并成一条, 列出全部行号
- 结果不受影响的写法不单列条目, 例如声明后未使用的变量、`scanf("\n")` 这类多余的读入、`gets` 之后多余的去换行步骤
- 只在测试不会出现的输入上出错的, 严重度降到 10 左右, 例如 `str2` 为空串时外层循环不前进
- 缺头文件、拼写错误这类独立缺陷单独成一条, 不并进其他问题里
- 转录本身拿不准的代码行末标 `(见额外校对表)`, 不据此提高严重度
- 文件完全没有问题时, 表格写一行 `| — | — |`, 正文写「未发现缺陷」并简述正确的部分
- 不自行增加题面没有的要求, 用额外数组之类明确违反题面的单独写成一条, 按题面违规计

## 严重程度

| 分数段 | 含义                             |
| ------ | -------------------------------- |
| 90-100 | 核心功能未实现, 或结果完全错误   |
| 60-89  | 主要用例结果错误, 逻辑有实质缺陷 |
| 30-59  | 仅边界或特定输入出错             |
| 10-29  | 输出格式偏差, 题面违规           |
| 0-9    | 语法笔误, 可读性, 过时写法       |

## 分析要点

- 第 1 题: 读入格式, `n` `m` 的行列含义, 翻转是交换还是倒序输出, 列分隔符与换行
  - 没有写 `scanf` 读入 `m` `n` 不算缺陷, 不单列条目, 也不扣分, 只关注矩阵元素的读入、翻转与输出
- 第 2 题: 读入方式, 大小写归一, 原地压缩, 结尾 `\0`, 是否使用额外数组
- 常见错误: 数组声明无长度, 循环变量超出 `for` 作用域, `scanf` 缺 `&`, 格式串写逗号, 用 `\0` 当删除, 循环按容量 120 遍历而不是按字符串长度
- 只按题面保证的输入范围判断, 输入一定是合法的
  - 不写「输入超过 119 个字符会越界写入」「未检查长度上限」「未处理 EOF」「未检查返回值」这类防御性写法, 既不算缺陷也不提建议
  - 数组容量小于题面给出的上限才算缺陷, 例如第 2 题开 20 字节而题面上限 119 个字符
  - 判断题面给的边界, 例如长度恰为 119 时 `fgets` 留下的换行, 属于合法输入下的实际错误, 照常写
- 先按「转录规则」跑编译检查, 记录 C99 与 gnu89 下的结果
  - 编译失败单独写成一条, 严重度按它对结果的影响定, 不因为无法编译就写成 90 以上
  - 拼写错误、缺头文件、漏分号、漏声明按 0-9 记, 对应实际扣分 0.1 到 0.5 分
    手写代码里这些问题很常见, 算法本身正确时不要据此抬高其他条目的严重度
  - 只在 gnu89 下告警的, 写明 C99 不通过、旧标准可通过
- 学生使用 `gets` 时补一条提示: 该函数在 C11 中已移除, 属于过时写法, 应改用 `fgets`

## 批量生成

文件数在 50 以上时, 用多个子 agent 并行写, 每个 agent 负责 8 到 10 名学生

- 先建一份共用的写作规范文件 (放在 `%TEMP%` 或 `/tmp` 下), 写清评议结构、档位表、两题判分要点、常见错误
  规范文件开头原样照抄「批改基调」两条, 子 agent 不读 SKILL.md, 只靠这份规范约束口径
  每个子 agent 的提示词只写「先读规范文件, 再处理下面这几个文件夹」, 不重复贴规范正文
- 先跑一遍全量编译, 把每个文件的 C99 与 gnu89 错误数存成表, 连同路径交给子 agent 查
  这样各 agent 的编译结论口径一致, 也不必各自重复跑 gcc
- 分组按学生文件夹切, 不把一个学生的两题拆给两个 agent
- 批量改写前先删掉旧的评议文件, 避免新旧混在一起

## 一致性复核

子 agent 并行写出的档位必然不一致, 全部写完后统一对齐一遍
实测 344 个条目里有 111 条需要改档

- 把全部条目的「文件名 / 编号 / 严重程度 / 标题」抽成一张表, 按缺陷类型聚类, 同一类缺陷只允许一个档位
  例如「`=` 写成 `==`」「缺临时变量」「循环增量写错」都属于单字符笔误, 统一记 45, 不按结果全错记 70 到 90
  「`scanf("%s")` 遇空格截断」「未处理大小写」「按容量 120 遍历」统一记 40
  「下标差 1」「用 `\0` 代替压缩」统一记 50
  「格式符或函数名写错」(`%c` 与 `%s` 互换, `putchar` 输出字符串, `getchar` 带参数) 统一记 50, 不按结果全错记 60 以上
  「变量名或下标写错, 但结构成立」统一记 45
  判断标准是改一个标识符后原思路能否跑通, 能跑通就按笔误记, 不按结果全错记 60 以上或 90
  「空函数」「伪代码」统一记 95, 有部分框架但核心缺失记 90
- 先按类型定表, 再逐个文件回写, 回写后用脚本复检表内数字与正文描述是否对得上
- 机械校验两项, 改动前后各跑一次
  - 行号不得超出对应 `.c` 的行数
  - 正文里「第 N 行 `代码`」引用的片段, 去掉空格与反引号后应能在第 N 行找到

# 评分建议

## 评分口径

- 先按「批改基调」一节: 纸面考试, 大一新生, 只判思路与结果
- 开始算总分前先提醒用户: 按手写代码的完成度细粒度给分, 最小单位 0.1 分, 不要凑整
- 这是手写代码考试, 语法层面的问题不等于思路错误
  拼写错误 (`supper`), 缺头文件 (`tolower` 未包含 `ctype.h`), 漏分号, 漏声明, 缺 `&`, 括号写错
  循环变量漏初值, 格式串分隔符写错 (例如 `%d,%d` 对应空格输入)
  这些大多只补一个字符或一句声明即可, 一律扣 0.1 到 0.5 分意思一下, 不按大项扣, 不因为编译不通过就重扣
- 变量名、数组名、下标起点写错, 若改一个标识符后思路立刻成立, 按笔误处理, 记 45 档, 不按功能未实现记 90
  例: 第 2 题命中后应在 `str1` 上左移, 学生写成 `str2[k] = str2[k + 1]`, 而外层扫 `str1`、内层扫 `str2`、命中即左移的结构完整, 属于此类
  评议里写「按这个笔误理解, 思路成立」, 同时写清正确写法, 便于学生对照
- 编译通过最多按附加 1 分计, 不能作为主要依据
- 判断重点放在思路与结果: 能否读入, 翻转或删除的逻辑对不对, 样例能不能得到正确输出
- 严重程度主要看思路是否成立
  思路正确, 只是读入、压缩或下标这类实现细节没处理好的, 记 30 到 50, 不按结果错误记到 60 以上
  例如循环里多调一次 `getchar`, 读入到换行为止的想法是对的, 记 40 即可
  只有思路本身不成立, 或功能没有实现, 才记 60 以上或 90 以上
- 列间用制表符、行末多一个空格、列间没有分隔符、用 `%5d` 加宽这类纯格式问题, 严重度记 1 左右
  实际扣 0.1 分, 或者不扣, 不因为这类细节影响总分
- 缺换行会破坏整个矩阵版式, 与缺分隔符同时出现时合并记 15 左右
- 输出循环的列数写成行数, 或把制表符与换行的分支写反, 都属于排版细节
  本意能看出是列间分隔、行末换行, 记 15 到 25, 不按逻辑错误记到 60 以上
- 严重程度表的 0-9 一段对应这类语法笔误, 90-100 只留给没有实现或结果完全错误的代码
- 分数保留一位小数, 按梯度细粒度给, 例如 10.1, 11.5, 13.8
  不要求整数分, 也不把分数集中到少数几个档位

# 两题的判分要点

第 1 题 (14 分)

- 上下翻转输出
- 真正交换行与只倒序打印都算正确
- 关注行列顺序, 空格与换行格式

# 人工复查
