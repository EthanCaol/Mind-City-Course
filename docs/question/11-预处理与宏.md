# 知识点 11 · 预处理与宏

## 说明 · 预处理指令与宏的三条黄金法则

预处理（`#` 开头）发生在编译之前，做的是纯文本层面的事：

| 指令                                      | 作用                                                                                  |
| ----------------------------------------- | ------------------------------------------------------------------------------------- |
| `#include`                                | 把 `stdio.h` 等头文件内容原样插进来                                                   |
| `#define` / `#undef`                      | 宏定义 / 取消宏定义（宏展开 = 文本替换）                                              |
| `#if` `#ifdef` `#ifndef` `#else` `#endif` | 条件编译：按条件决定哪段代码参与编译（`#ifndef X` … `#endif` 就是"头文件卫士"的写法） |

宏是"文本替换"，不是函数调用！ 宏的参数在展开时直接原样代入，不会自动加括号。

!!! note "宏的三条黄金法则"

    1. 每个参数都加括号：`((x) * (x))` 而不是 `x * x`；
    2. 整个表达式再加一层括号：`(x + 1)` 而不是 `x + 1`；
    3. 能不用宏就不用，优先 `static inline` 函数或 `const` 常量。

    原因：宏没有类型检查；参数会被求值多次（`SQUARE(i++)` 会让 `i` 自增两次）；

    而 `static inline` 函数有类型检查、参数只求值一次，且同样没有函数调用开销。

### 1 · 宏展开陷阱 · 函数式宏必须加括号

以下程序的运行结果是？

```c
#define SQUARE(x) x * x

int result = SQUARE(2 + 3);
printf("%d\n", result);
```

- A. 25
- B. 13
- C. 9
- D. 11

??? note "答案"

    D（11）

??? note "解析"

    宏展开是纯文本替换：

    ```c
    SQUARE(2 + 3)  →  2 + 3 * 2 + 3
    ```

    按优先级算：`2 + (3*2) + 3 = 2 + 6 + 3 = 11`。✅（如果它是函数，答案才会是 25。）

    正确写法必须给参数和整体都加括号：

    ```c
    #define SQUARE(x) ((x) * (x))     // → (2+3) * (2+3) = 25
    ```

    为什么"两层括号"缺一不可？（这是本题的评分点）

    | 写法                     | `SQUARE(2+3)`   | 结果 | 够不够用                                                                  |
    | ------------------------ | --------------- | ---- | ------------------------------------------------------------------------- |
    | `#define M(x) x*x`       | `2+3*2+3`       | 11 ❌ | 错                                                                        |
    | `#define M(x) (x)*(x)`   | `(2+3)*(2+3)`   | 25 ✅ | 本题够用，但换个场景仍翻车：`100/M(10)` → `100/(10)*(10)` = 100，而不是 1 |
    | `#define M(x) ((x)*(x))` | `((2+3)*(2+3))` | 25 ✅ | 永远安全                                                                  |

    - 参数加括号：防止 `2+3` 被乘法的优先级"劈开"（本题就是死在这里）。
    - 整体加括号：防止宏的结果被外层运算符抢走优先级（如上面 `100/M(10)` 的例子）。
    - `2 + 3 * 2 + 3` 的读法：`*` 比 `+` 优先级高，所以先算 `3*2`，再从左到右加：`2+6+3 = 11`。

    > 易错：选 A）25 —— 那是把它当函数算的结果（材料上只给出 D 与展开式，其余选项未逐项解释）。

    > 宏没有类型、没有优先级保护，参数和整体都要加括号，两层一层都不能少。

### 2 · 宏展开陷阱（第二道）· 展开后完全按运算符优先级走

以下宏的输出结果是？

```c
#define ADD(x, y) x + y

printf("%d\n", ADD(3, 4) * 2);
```

- A. 14
- B. 11
- C. 18
- D. 7

??? note "答案"

    B（11）

??? note "解析"

    和上一题（`SQUARE(2+3)`）是同一个考点的第二道，只是陷阱从"宏内部被劈开"换成了"宏的尾巴被外面的运算符抢走"：

    ```c
    ADD(3, 4) * 2  →  3 + 4 * 2
    ```

    宏是纯文本替换，展开后的表达式按 C 语言自己的运算符优先级走：`*` 比 `+` 高，所以先算 `4 * 2 = 8`，再算 `3 + 8 = 11`。✅

    选项对照：

    - A）14 —— 把宏当成函数算的结果：`(3+4)*2 = 14`。这是最诱人的错误答案。
    - B）11 —— 正确答案：`3 + 4*2 = 11`。
    - C. 18、D）7 —— 其余干扰项（材料上只给出了 B 与展开式，未逐项解释）。

    正确写法：整体加括号即可（本题参数本身就是单个数字，参数括号可省，但仍建议都写全）：

    ```c
    #define ADD(x, y) ((x) + (y))     // → ((3) + (4)) * 2 = 14
    ```

    !!! warning "写错时反而看不出问题"

        改对之后答案就从 11 变成 14 了——宏写错时，结果可能"看起来很正常"，这是它最坑的地方。

    > 宏展开后没人替你"兜底"，一切按优先级走，所以参数要括号、整体更要括号。

    两题对照记忆：

    - `#define SQUARE(x) x*x` —— 参数 `2+3` 被劈开（`2+3*2+3`）；
    - `#define ADD(x,y) x+y` —— 整个宏 被外面的 `*2` 咬住（`3+4*2`）。

    一个是"参数不加括号"，一个是"整体不加括号"，正好是黄金法则的前两条各踩一次。

### 3 · 宏与函数的选择

!!! note "扫描件里没有留存题面文字"

    扫描件里这道题的题面文字没有留存，只留下了这段程序。下面的题意是按代码反推的，不是题干原文，别当题干背。

    题意（推测）：输入 `m`、`n` 和一个字符串 `s` 及 `m×n` 矩阵。

    若 `s` 为 `"Col"` 或 `"1"`，输出列和范数（各列元素和的最大值）；

    若 `s` 为 `"Row"` 或 `"Infinity"`，输出行和范数（各行元素和的最大值）；否则输出"输入的范数类型不合法"。

```c
#include <stdio.h>
#include <string.h>

#define max(a,b) a>b?a:b

int main() {
    int m, n;
    char s[10] = {0};
    int A[100][100] = { 0 };
    int norm = -1;
    scanf("%d %d", &m, &n);
    scanf("%s", s);
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            scanf("%d", &A[i][j]);
        }
    }
    if (strcmp(s, "Col") == 0 || strcmp(s, "1") == 0) {
        for (int j = 0; j < n; j++) {
            int col_sum = 0;
            for (int i = 0; i < m; i++) {
                col_sum += A[i][j];
            }
            norm = max(norm, col_sum);
        }
        printf("该矩阵的列和范数为%d", norm);
    }
    else if (strcmp(s, "Row") == 0 || strcmp(s, "Infinity") == 0) {
        for (int i = 0; i < m; i++) {
            int row_sum = 0;
            for (int j = 0; j < n; j++) {
                row_sum += A[i][j];
            }
            norm = max(norm, row_sum);
        }
        printf("该矩阵的行和范数为%d", norm);
    }
    else {
        printf("输入的范数类型不合法");
    }
    return 0;
}
```

??? note "答案"

    !!! quote "答案里的宏写法"

        题中使用的宏是：

        ```c
        #define max(a,b) a>b?a:b
        ```

        它在本题的调用方式 `max(norm, col_sum);`（以及 `max(norm, row_sum);`）下恰好不出错，但写法本身是不合格的，考试中应写成：

        ```c
        #define MAX(a, b) ((a) > (b) ? (a) : (b))
        ```

??? note "解析"

    同一个"不加括号"的坑，为什么本题侥幸没事？

    ```c
    max(norm, col_sum);   // 展开为  norm>col_sum?norm:col_sum   —— 独立的表达式，外层没有别的运算符来抢优先级
    ```

    但换个用法立刻出事：

    ```c
    max(a, b) + 1        // → a>b?a:b + 1
    ```

    这里 `?:` 的优先级低于 `+`，实际被解析成 `a>b ? a : (b+1)`——结果多加了 1。

    正确的加括号版本就不会有这个问题：`((a) > (b) ? (a) : (b)) + 1` 展开后括号把它保护住了。

    > 同一道题的另一个隐形坑：`max(norm, col_sum)` 的参数被求值两次（`a>b` 算一次、取用时再算一次）。

    > 这里的实参是普通变量，没有副作用，所以看不出问题；如果写成 `max(i++, 5)`，`i++` 就会执行两次——这是"能不用宏就不用宏"的最强理由。

    > 本题的写法到此为止只是"不够优雅"，`static inline` 或 `#define MAX(a,b) ((a)>(b)?(a):(b))` 都是更好的选择。
